Spherical fault-network analysis
================================

The spherical extension separates two concerns:

``modules.spherical``
   Dependency-light great-circle geometry, graph direction and sampling,
   fault correlation, and slip calculations.

``modules.spherical_surface``
   Loading of prepared numerical-model rasters, periodic skeleton extraction,
   and raster sampling for the teaching workflow.

Coordinate and unit conventions
-------------------------------

Graph node positions are always ``(longitude, latitude)`` in degrees, with
longitude wrapped to ``[-180, 180)``. Functions with separate arguments use
the explicit ``(latitude, longitude)`` order shown in their signature.
Great-circle distances are kilometres by default. Input velocity units and the
time interval passed to ``calculate_slip_sphere`` must be mutually
consistent; Fatbox does not silently rescale them.

There is no hemispheric filter. Southern Hemisphere nodes are processed in the
same way as Northern Hemisphere nodes. Filtering a study region, when desired,
should be an explicit preprocessing step owned by the calling workflow.

Minimal graph workflow
----------------------

.. code-block:: python

   import networkx as nx
   from modules import spherical

   graph = nx.path_graph(3)
   nx.set_node_attributes(
       graph,
       {0: (178.0, -30.0), 1: (179.0, -30.0), 2: (-180.0, -30.0)},
       "pos",
   )
   spherical.connect_across_dateline(graph)
   spherical.calculate_direction(graph, cutoff=1)
   samples = spherical.calculate_pickup_points(graph, factor=0.5)

Prepared surface-raster workflow
--------------------------------

The beginner tutorials read compressed mesh-free archives distributed under
``tutorials/numerical_modelling/data/spherical_example``. They contain only the
regular strain and velocity rasters, output number, time and grid shape. The
original mesh, full strain tensor and unrelated numerical-model fields are not
needed. The original model may have been produced by any software, provided
the prepared rasters follow the documented coordinate and unit conventions.

.. code-block:: python

   from modules import spherical_surface

   surface = spherical_surface.read_surface_archive(
       "spherical_surface_00230.npz"
   )

   graph, mask, skeleton = spherical_surface.extract_fault_graph(
       surface["strain"], threshold=5e-16, minimum_component_size=20
   )
   samples = spherical_surface.sample_velocity_difference(
       graph, surface["velocity"], pickup_degrees=0.5
   )

The user-facing, step-by-step workflow is provided in
``tutorials/numerical_modelling/tuto_num3_spherical_extraction.ipynb`` and
``tuto_num4_spherical_correlation_slip.ipynb``. The first notebook demonstrates
one output before extracting an arbitrary ordered sequence. The second first
explains one graph pair, then assigns persistent identities progressively with
``n-1``/``n-2`` recovery, records split/merge families, and calculates slip for
every model interval.

Installation and notebook order
-------------------------------

From the Fatbox repository root, create the tutorial environment, activate it
and start JupyterLab:

.. code-block:: console

   conda env create -f environment-spherical.yml
   conda activate fatbox-spherical
   jupyter lab

Select the ``fatbox-spherical`` kernel in JupyterLab. Run
``tuto_num3_spherical_extraction.ipynb`` before
``tuto_num4_spherical_correlation_slip.ipynb`` because Tutorial 4 loads the
graphs generated by Tutorial 3.

The validation commands are:

.. code-block:: console

   pytest -q
